Dig101 is back — digging into mechanics behind everyday Go.

Two common iteration forms: for and for-range. Range has sharp edges — the usual traps below.

Update: Go 1.22 gives each iteration its own loop variables, so the classic “shared loop var” bugs below do not apply on 1.22+ unless you use an older release.

0x01 Can you collect pointers to every element?

No — same surprise on []int{1, 2} or map[int]int{1:1, 2:2}.

for-range is syntactic sugar. The compiler copies the container (for arrays/slices/maps as the spec defines), and v is one variable reused each iteration. Taking &v yields one address; after the loop it holds the last value (2, 2).

0x02 Does ranging stop if you append to a slice?

Yes — iteration length was fixed from the copy at range entry; appends to v do not extend this loop.

0x03 Large arrays and wasted copies

Wasteful — ranging copies the whole array.

Options:

  • for i, n := range &arr
  • for i, n := range arr[:]

Quiz: why don’t huge slices and maps pay the same full-value copy? (Hint: what the range clause actually duplicates.)
