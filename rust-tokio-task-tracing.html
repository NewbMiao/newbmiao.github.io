tokio-console — observe Tokio task scheduling and runtime behavior

Rust async is built around task scheduling—tasks are the language-level unit the executor moves between.

Can you see that scheduling happen? Yes. Tokio ships tokio-console: a live view of tasks, polls, and wakeups that helps when you’re debugging latency or learning how the runtime behaves.

Setup

Your program reports events through console-subscriber; the tokio-console CLI aggregates and displays them.

What you see

Switch between task view (t) and resource view (r).

Tasks

Per task you get time buckets (Total, Busy, Sched, Idle), poll counts, and state.

For what those timers mean, see task-scheduled-time-in-console.

Arrow keys move the selection; Enter drills into a row (e.g. task-t2) for waker details and finer-grained timing—handy for spotting stragglers.

Resources

The resource view lists which async primitives were exercised.

Expand a row for per-call timing—for example the three semaphore_wait.acquire calls on t2.
