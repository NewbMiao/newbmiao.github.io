OPA Rego — functions vs virtual documents and when to use each

Contents

  1. 1. Functions
  2. 2. Virtual documents
  3. 3. Pick one

Rego gives you two ways to package logic: functions and virtual documents. They overlap on paper; in practice the choice comes down to whether you need a relation you can iterate.

We’ll use a file list in input and ask: which paths look like config files?

Functions

Rego allows multiple rules with the same name — overload by arity and by how arguments unify. Think lightweight pattern matching, not Java generics.

Properties:

  • Default return is true/false (undefined → false)
  • Or assign with name(args) = value { ... }
  • Same name only if arity differs (or inputs unify differently)
  • Same inputs must always yield the same outputs

Virtual documents

A virtual document is a finite relation you can query and enumerate — getFileNames[x] defines the set of names.

getFileNames[x] { ... } is shorthand for getFileNames[x] = x { ... } — each successful x becomes a member.

Pick one

Ask:

  • Do you need to enumerate results?
  • Is the output finite for a given input?

If either is yes, lean virtual document. Pure transforms on known arguments → function.
