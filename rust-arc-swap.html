arc-swap — atomic Arc swaps vs RwLock for config

Contents

  2. 2. arc-swap

In Rust, config that threads read while another thread updates it often shows up as Arc<RwLock<T>>. You can also reach for arc-swap. What’s the difference?

Typical shape: one thread updates config while others keep reading—they should see the new snapshot without restarting the process.

Run it and you may see the reader stuck on the old config — and "Updating config done" never prints. Why?

This is a deliberate footgun: a read guard keeps the lock held. More readers can pile on, but no writer can take the lock until every read guard is dropped.

arc-swap

With RwLock, you have to think about how long you hold locks. Reads and writes are not one atomic step, so the code is easier to get wrong and deadlock.

arc-swap is aimed at that pain: swap the whole Arc atomically so readers and writers do not fight over a lock guard lifecycle.

The flow is more direct. For read-mostly, occasionally-updated data, arc-swap is often worth trying.
