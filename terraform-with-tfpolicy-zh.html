没学过 Sentinel / OPA？Terraform 规则这回直接换了！

这些年做运维有个东西深有体会：有些技术，没学过就不用学了。

以前管 Terraform 规矩，老路子要啃 Sentinel / OPA。

今年倒好，官方 tfpolicy GA 了——规则治理的新选项，会写 HCL 就能上手。

tfpolicy 管什么

这回更细了，管的就是 Provider、Module、Resource 这三层。上下文 Terraform 自己给你，不用再从 Plan JSON 里抠字段。

graph LR
  subgraph Setup
    PP["Provider Policy
来源、版本"]
    MP["Module Policy
来源、版本"]
  end
  subgraph Plan
    RPp["Resource Policy
计划里的资源属性"]
  end
  subgraph Apply
    RPa["Resource Policy
部署后才定的属性"]
  end
  MP --> RPp --> RPa
看什么 典型例子
Provider 从哪来、什么版本 约束 provider 版本或来源
Module 从哪来 只允许公司发布的 module / 本地 module
资源属性 Storage 别开匿名公网

Setup 在 provider 还没下来就能拦；Plan、Apply 各管一段 Resource。

以前写 Rego，多是 Plan 跑完，导 JSON，自己遍历。debug也隔了一层，不够直接了当。

tfpolicy 至少不用先当 JSON parser。

0成本上手：官方库 + Agent Skills

HashiCorp 还推了 Terraform Agent Skills。写规矩这回都0成本了。(AI Token：对，我没成本)

terraform-policy 这个 skill 能干：

  • 按需求写 .policy.hcl
  • 写、调 .policytest.hcl
  • Sentinel 往 Terraform Policy 迁
  • 整库搬家

细活会分到 tfpolicy-author、tfpolicy-test。

需求说清楚就能扔给 AI。比如：

帮我写一条 Azure Policy：Storage Account 禁止匿名公共访问，顺便给正向和反向的 policytest。

出稿以后，tfpolicy validate、tfpolicy test 照样跑一遍。

拦什么、例外谁批，还得你自己拍板。

规则也不用从零抠。Pre-written Terraform Policy Library 有一堆现成的：

云平台 Policy 数量
AWS 423
Azure 82
GCP 68

Azure 那八十多条，也是基于 CIS Microsoft Azure Foundations 6.0.0。Storage、SQL、Key Vault、Network、IAM 都有。

这都可以先套官方，按需再往里加自定义的。（别的云就不好意思了，😄）

现在真是方便了，回想起之前还在用OPA policy。拿两个例子回顾一下吧

痛点一：Policy 排队，拿不到Run 结果

TFC 上 workspace 一多，Plan 过了还得等 Policy Evaluation。

高峰了好几个项目一起跑。有时Plan 早好了，Bitbucket迟迟拿不到结果，人卡在 OPA 队列里转圈。

等后边TFC上一看有的其实早跑完了，但太多，传回Bitbucket没接上。

现在这种事 CI pipeline上 tfpolicy 就能跑，都不用非到Policy Evaluation那一步。

痛点二：拦 Provider 源，得啃 Plan JSON

阿里云 Provider 曾有过两个源：hashicorp/alicloud 老的，aliyun/alicloud 才是现在建议用的，不声明，默认就是hashicorp的。

混着用，required_providers 打架。Plan 里还刷弃用告警， 国内网络问题也很麻烦。

之前用OPA 得分析：resource_changes 和 configuration.provider_config。

Rego 花点时间也写得出来。

现在同一条规矩，tfpolicy 盯 Provider 元数据就行。

Setup 阶段就能红。源不对，直接不用plan了。

总之，是早学早好，晚学不用学了！
